**Goal:** Run the lines charts of the current defaults on the NVIDIA nodes of ifi (RTX 2070, partition IFIgpu2070), to see whether copylib behaves there like on gpuc4 (discrete GPU over PCIe).

**Result:** Without copylib (Celerity's CUDA backend, `cudaMemcpy2D/3DAsync`) device-to-host strided copies plateau at about 200 MB/s; copylib staging is 20-30x faster there (4-6 GB/s), the host kernel is slower than the native path (110 MB/s). Device-to-host looks like gpuc4: contiguous M = 1 reaches about 15 GB/s, staging about 5-6 GB/s, and the host kernel only about 110 MB/s (60 MB/s at the largest sizes), i.e. the same collapse over PCIe. Host-to-device first access is not usable on this setup: all three lines coincide and grow linearly with the size (about 3 GB/s at 1 GB), also for the contiguous native path, so the measurement is dominated by something other than the copy.

# NVIDIA nodes of ifi (2026-10-06)

- **Hardware (`probe.sbatch`):** gc1-7, 4x GeForce RTX 2070 (8 GB, PCIe 3.0 x16), Threadripper 2950X (32 threads), 125 GB, CUDA toolkits 11.7-12.6, 12 h limit; open to us through the group `ifi-gpu-extern`. Not exclusive by default, the benchmark job asks for `--exclusive`.
- **Toolchain (`setup_nvidia.sh`, job `setup_nvidia.sbatch`, about 45 min on a node):** LLVM 20.1.8 with the NVPTX target (`install/llvm-cuda`), AdaptiveCpp 25.10 with the CUDA backend (`install/acpp-cuda`), Celerity at 2dda28f (`install/celerity-acpp-cuda-bench`) and the transfer programs (`build/bench-transfer-acpp-cuda-bench`), all next to the AMD builds. DPC++ is not available (our nightly has the HIP backend only). `strided_transfer` and `block_transfer` ran with `Check: ok`.
- **Run (`job_bench.sbatch`, `strided_{stg,hk}_defaults.yaml`):** the current defaults for staging and the host kernel, AdaptiveCpp, M 1 and 2, N 1..2^28, 3 iterations + warm-up, one exclusive node (gc3); all 348 runs ok. Charts: `../02_comparison/lines_defaults_nvidia.png` (host-to-device) and `lines_defaults_d2h_nvidia.png` (device-to-host). No SDMA setting exists on NVIDIA, and the earlier code states are not built there.
- **Without copylib (`strided_native_copylib_off.yaml`, `CELERITY_COPYLIB=off`, N up to 2^23, then `strided_native_copylib_off_large.yaml` for 2^24..2^28 (the cap came from the slow AMD native path and was not needed here); M 1 and 2; 144 runs ok in the first part):** the build has Celerity's CUDA backend (`CELERITY_ENABLE_CUDA_BACKEND=ON`, `sycl_cuda_backend.cc`), which copies strided regions with `cudaMemcpy2DAsync` / `cudaMemcpy3DAsync`. For 4-byte rows that is slow device-to-host: about 0.2 GB/s from 64 Ki rows on (staging 0.65 to 4.3 GB/s there, geometric mean 11x faster; host kernel 0.55x). Host-to-device first access is the same for all (staging 1.04x, host kernel 1.18x of native), see the caveat below.
- **Host-to-device caveat:** the first access takes about 0.15 s even for 4 bytes and about 0.33 s at 1 GB for both M = 1 and M = 2, so these numbers are not a copy rate. A likely cause is first-use cost of the CUDA backend (context, JIT) inside the timed region; not investigated.
